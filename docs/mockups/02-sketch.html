Sketch on paper

The sketch is the page. Geometry, dimensions, and constraints are drawn in ink; the only colour is the highlighter on the thing you are changing right now.

What this study tests

  • Tools are a line of words, not a toolbar. They appear only in sketch mode, with the shortcut beside each one.
  • The dimension editor replaces the label. One control holds the value, the unit, and driving/reference. Enter commits, Escape or a tap outside cancels — no apply/cancel buttons, because the value is the thing you are already looking at.
  • Projected reference geometry is visibly different. Dashed, labelled, fixed, and never selectable as user geometry.
  • The background is the snap grid. Change the spacing from the footer; the scale bar shows one cell at the current zoom (100%). Snap can be switched off without hiding the grid.
  • The view footer is real. 100% opens 50 / 100 / 200 / fit. The grid and scale bar follow the zoom. Every control is focusable; coarse pointers get larger targets.
  • The timeline is still here. Sketching is a step in history, not a separate application. The step name is the identifier; “rename” lives in the timeline detail.

Open questions

  • Should the tool line stay visible for the whole sketch, or fade once a tool is chosen?
  • On touch, is “tap outside cancels” discoverable enough, or does the editor need a visible done affordance?
  • Do projected edges need a global show/hide control, or is the dashed style enough?
  • Should the grid hide automatically when zooming out makes the cells too dense?
The highlighter is never decoration: it means “current”, “selected”, or “changed”. Everything else is ink on paper. The grid is the opposite: it is structure, so it stays quiet until you use it.
