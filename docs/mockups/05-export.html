Export for the printer

Export is the end of the loop, not another application mode. It is a one-page typographic summary of what the printer is about to receive.

What this study tests

  • The model stays visible. You are exporting the thing on the page, not a file in a dialog.
  • Print checks are plain sentences. Watertight, one shell, millimetres, build volume — no dashboard.
  • History is not the mesh. The STL is generated from the current rebuild state; changing a step changes the export.
  • One primary action. The highlighter is on “export STL” because that is the only decision left.

Open questions

  • Should export be a history step that freezes a mesh, or always derived?
  • Do we need a print-orientation preview, or is “fits the build volume” enough for v1?
  • Would a 3MF export with units be more useful than STL for the target workflow?
The target loop is sketch → model → print. Export is a first-class page because it is the actual end of the user's job.
