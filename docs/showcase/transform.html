Move, copy and align

Two ways to put a body where you want it: transform it directly (move / copy), or relate it to another body (align). Both keep the same preview grammar — the result is highlighter-tinted, the original is a faint ghost until you commit.

What each does

  • Move / copy translates and rotates the block, with a create copy toggle: on, the original stays and a tinted copy appears; off, the original becomes a ghost and the result takes its place.
  • Align snaps the block to the reference plate per axis — none / left / centre / right, and for Z below / centre / on top. A guide line shows where the block travels.

Open questions

  • Does a body move persist as a feature (so it can be re-edited), or is it a one-shot transform like the sketch move/copy? This study leans toward a persistent operation, matching M6.0.
  • Should move/copy be draggable in the viewport (Fusion's free move), or is the exact numeric box enough for v1?
  • Align needs a reference: a body, a face, or a datum plane? This study only uses a body's bounds.
  • How does align pick the moving body when several are selected?
