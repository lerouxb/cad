Selecting opens a popover

Sketch inputs used to look nothing like the feature popovers: a floating "selection card" with a horizontal constraint bar. This study folds them into the same family. Selecting geometry opens a selection popover with the same anatomy as every other popover — it is simply a palette of immediate actions rather than a form with a commit pair.

The three shapes

  • Selection popover — the actions for what is selected: constraints, construction, fix, delete. Chips act immediately, so there is no apply/cancel. Draggable, like every popover.
  • Inline editor — a single value at the thing it belongs to. Select the dimension and the editor replaces its label, carrying the value, the unit and driving/reference in one control. Enter commits, Escape or a tap outside cancels; there are no buttons.
  • Operation popover — the multi-parameter forms (extrude, pattern, combine), with a commit pair.

Open questions

  • On touch, is “tap outside cancels” discoverable enough, or does the dimension editor need a visible done affordance?
  • Do the constraint chips need grouping (position / size / pattern), or is one wrapped row enough?
  • Should the popover show the full selection list, or just the count and the geometry?
The old study-02 "selection line" is superseded: a bottom strip is still a bottom bar, and it drifts. The popover is one shape to learn.
