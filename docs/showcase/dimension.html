Driving or reference, at a glance

A dimension is two things: a value and a kind. Driving means the value constrains the geometry; reference means it only measures it. The editor used to make both look like a form field, and the kind was a single button whose label you had to read to know what it would do.

The interaction

  • The kind is a segmented control — driving / reference, both always visible, the current one filled. The same control sets the kind when you place a dimension, so there is one thing to learn.
  • The value is a field only while driving. A reference dimension's value belongs to the geometry, so it renders as a readout — parentheses, dim italic ink, a measured tag. There is nothing to type into, because there is nothing to set.
  • Release and constrain. Switching driving → reference releases the constraint (the label gains parentheses and the sketch gains a DOF). Switching back adopts the current measurement as the driving value.
  • Enter or click out commits; Escape reverts. There is no apply button — but the label visibly changes on commit, and the DOF counter moves, so you can see it took.

Notes

  • A reference dimension is not a disabled form field. Dimming an input still says "you could edit this if you tried". A readout says "this number is an observation".
  • Both surfaces (place and edit) use the same driving / reference control, so the kind never changes meaning.
  • The delete stays quiet, in the footer of the editor, where it already was.
The bug this came from: switching an existing dimension to reference was silently dropped, because a dimension with no driving field could not be changed — see INTERACTION.md. A change that cannot be applied must be visible, never swallowed.
