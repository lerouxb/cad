One boolean language

Extrude, revolve and every future solid feature offer the same four operations — new body, join, cut and intersect — in the same order, with the same words and the same preview colours. New body keeps its result-body preview; join highlights the material it adds; cut and intersect become unmistakable.

new body · join · cut · intersect open the contract one row · one preview grammar

The four operations

One profile, one operation row. The result body is always normal material. The material a join adds is highlighter; only the material a cut removes is red; intersect ghosts what it discards.

New body

A separate body. Existing bodies stay untouched, even where the new body overlaps them.

No diff tint: the whole body is new. It never washes the existing body.

Join

The added material is highlighter. The target and the overlap that was already material stay normal.

Tint only the tool minus target. The overlap is already material; do not repaint the whole union.

Cut

The removed volume is red. The cutter outside the body is a ghost, so the tool still reads.

The red plug is the material the cut takes away. The result body stays normal.

Intersect

Only the shared volume survives. The target and the rest of the tool are ghosts — never red.

The overlap is the result; ghosting the outside is what makes it different from a cut.

The operation row

One segmented row in the feature form, all four options visible, in this order. No dropdown, no per-feature vocabulary. The summary uses the same word.

The row, in an extrude

The default is new body with no body in the document, join when there is one. There is no silent change after the row is touched.

Cut is red, intersect is ghost

Both operations discard material. The colour is the difference: a cut marks the material that disappears in red; an intersect leaves the result normal and ghosts everything outside it.

Cut

The result body is normal with the red plug showing what the cut removes.

Intersect

No red. The kept overlap is normal; the target outside it and the tool above it are ghosts.

The same pair, side by side

A user should never have to read the operation word to tell these apart.

Offset faces reuses the grammar

Offset faces is a modification, not a boolean: there is no operation row, and it always edits the selected body. But out adds material in the highlighter and in removes it in red, over a ghost of the pre-offset body.

What the step says

The output chip says create vs reference, not which boolean ran. The operation word lives in the step meta, next to the distance.

Extrude 2 through all · cut →body

Extrude 3 12.0 mm · intersect →body

`−` stays “consumes this body”; cut/intersect reference the surviving body with `→`.

When it does not work

Cut and intersect need a body and a non-empty result. Both are visible errors; the last good body stays and the operation never changes itself to something that would work.

The rules in one place

  • Four operations, four words. `new body`, `join`, `cut`, `intersect` — always in that order, in every feature form.
  • One segmented row. All four visible; no dropdown and no per-feature synonyms. The summary uses the chosen word.
  • Join is added material. Highlight tool minus target; the target and the overlap that was already material stay normal. Never repaint the whole union.
  • New body is a whole body. Keep its result-body preview; tinting it all would read as a selection.
  • Cut is red. The removed volume is cut red; the tool outside the body is a ghost; the result body stays normal.
  • Intersect is ghost. The kept overlap is normal, everything outside it is a ghost. Intersect never uses red.
  • Offset faces is not a boolean row. Out/in reuses the add/remove/ghost grammar and always modifies the same body.
  • No silent operation change. The draft default is new body/join; after that, an impossible operation is a visible error.
  • Cut and intersect need a base and a non-empty result. No base, no overlap or an empty result is an error, never an empty step. An end that stops on the target surface leaves nothing to remove; use blind or through-all (cut).
  • Through all is cut-only. The other operations need a finite tool.
  • The chip is create vs reference. `+ body` for new body, `→ body` for join/cut/intersect; `−` stays “consumes”.

design notes · booleans

The operation row and the preview

Extrude, revolve and every future solid feature use the same four operations. This study pins the words, the order, the control and the preview so the app cannot drift one feature at a time.

What this study settles

  • The set is complete: new body, join, cut, intersect. Combine reuses join/cut/intersect; split and offset are not booleans.
  • The row is one segmented control, all four options visible, same order everywhere. `new body` is spelled out; it is never `new`.
  • Cut is red, intersect is ghost. The result body is never repainted; only the diff layer is tinted.
  • Join highlights the material it adds. Tool minus target is highlighter; the target and the existing overlap stay normal. New body keeps its result-body preview.
  • Offset faces reuses add/remove/ghost but has no operation row: out/in is a signed distance, not join/cut.
  • No silent operation change, no empty step. Cut/intersect need a base and a non-empty result.

Open questions

  • Does intersect ship with extrude/revolve in v1, or wait for Combine?
  • Does a disjoint join create a separate body or error? Current behaviour stays for now.
  • Should the cut red become a semantic token instead of the two viewer literals?
  • Should the tool outside the target be ghosted for a cut, or only the removed overlap?
