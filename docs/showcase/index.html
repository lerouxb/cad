Preview before commit

Pattern, mirror and offset all need a configuration before they can create anything, and the sketch is the only place that configuration can be judged. So each tool opens a popup next to the geometry it will change, and every control edits a live preview on the canvas.

The preview grammar

  • The selection stays the original. It is ink with the highlighter wash behind it — the most prominent thing on the page.
  • What the tool adds is a preview. New geometry is dashed and faint, so it reads as a proposal you can still change. It is never highlighter-coloured: the highlighter means current or selected, and a preview is neither.
  • Parameters live on the geometry. Direction arrows, instance ticks, a sweep arc, a mirror line and an offset arrow are drawn on the canvas and are draggable.
  • The popup is context-sensitive. It exists only while a tool is active, shows only the rows that apply, and disappears in select mode.

Objects, not one-shot edits

  • Apply keeps an object. The preview becomes real geometry and a persistent object — a pattern, mirror or offset with its parameters — the way a constraint persists.
  • The object has a badge. A small glyph and name sit on the geometry it governs. Click it (or the geometry) to select the whole object; the highlighter washes every piece it made.
  • The selection line is the edit handle. Selecting an object shows its name, parameters and edit / delete — the same line the app already uses for dimensions and constraints.
  • Edit reopens the tool. Editing loads the object's own parameters back into the popup, previews the change, and updates the object on apply. Delete removes everything it made.
  • The timeline is the permanent home. While the sketch step is active, its detail line lists the sketch's objects by name, so they are discoverable even with nothing selected.

What this study tests

  • Does a single preview grammar cover pattern, mirror and offset?
  • Is a dashed, faint copy distinct enough from the original selection in both themes and all four highlighter colours?
  • Is a persistent object obvious enough to re-find later — badge, selection line, and timeline list together?
  • Is the popup next to the geometry better than a docked inspector?

Decided

  • These are sketch objects, not history steps. A pattern, mirror or offset is an object owned by the sketch step — the timeline lists it in that step's detail, the way a constraint persists. (A body-level pattern / mirror / offset would be its own history step; that is a separate, later thing.)
  • A stale reference is surfaced, not silently re-run. Provisional — revisit once there is a real case to look at.

Open questions

  • Is a circular pattern always about a sketch point, or also a projected edge or axis?
  • How should an offset handle open chains and self-intersections?
The highlighter is never decoration: it means current, selected, or changed. A preview is a proposal, so it stays ink — dashed, faint, and easy to tell apart from the thing you already chose.
