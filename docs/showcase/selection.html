Select, then act

Selection is not a command. A click selects an object; the selection popover holds the constraints, measurements, edits and feature commands that apply. This study writes down every family, what can mix, what box/lasso and Backspace do, and where a new feature begins.

one family at a time · geometry + dimensions may mix open the contract

One selection language

The sketch and the model are the same paper. A selected line or edge is a highlighter block under an ink centerline — never a single opaque highlighter line. A face or region is a wash with the ink boundary still visible; a point is a marker fill with an ink ring; hover is the same block at lower opacity.

Ordinal · mono detail · one remove. The ordinal is the position in the set; removing renumbers. Stable refs stay in the document; the selection popover keeps stable labels, the form lists the picked set.

Inputs and their lists come before the value. The footer summary is value · input for a modification and size · operation · input for a boolean. The list is not repeated in the summary.

The rules in one place

  • Select first, act second. A click never creates a feature; the selection popover holds the commands.
  • Feature chips start drafts. `extrude…`, `revolve…`, `new sketch`, `offset face…`, `shell…`, `fillet…`, `chamfer…` open the relevant draft; they do not apply immediately.
  • A profile is not a face. A profile offers `extrude…` / `revolve…`; a face offers `new sketch` / `offset face…` / `shell…`, never extrude.
  • Selection looks the same everywhere. A selected line/edge is a highlighter block under an ink centerline; a face/region is a wash with the ink boundary; a point is a marker fill with an ink ring; hover is the same block at lower opacity. Never a single opaque highlighter line.
  • Inputs inside a form are rows and lists. Model faces/edges are always live on the stage; profiles switch to the sketch; an axis/support uses pick. Every multi input lists its items with remove, before the value. See PICKS.md.
  • One family at a time. Geometry + dimensions is the one allowed mix; a constraint, profile or another model family replaces.
  • Any type mix inside geometry is allowed. Two lines, a line + arc, a point + line: the chips come from what that exact set supports.
  • Shift toggles inside the family. Shift on an incompatible family is blocked; a plain click replaces.
  • Box/lasso respect the filter. Normal sketch marquees geometry/dimensions; profile mode marquees regions; model marquees edges/faces.
  • Backspace deletes the selection. Sketch geometry and dimensions are deleted in one undo; constraints are removed; profiles are cleared; model edges/faces are a no-op.
  • Reference geometry is click-only. It can be a constraint/dimension participant, but it is never marquee-selected or deleted.
  • Empty groups vanish. Show only applicable chips; if none apply, say so and leave delete.
  • Selection stays ephemeral. Not document state, not undoable; the order is only for the current gesture (the symmetric axis).

design notes · selection

Selection is not a command

The old app had a few direct shortcuts: clicking a profile started an extrude draft, and box/lasso in the sketch picked profile regions. That is convenient once, and confusing every other time. This study separates the two acts: select the thing, then choose an action from the popover.

What this study settles

  • A profile is selected, not extruded. The profile popover has `all / voids / auto`, `extrude…` and `revolve…`; a chip starts the draft.
  • A face is a support. The face popover has `new sketch`, `offset face…` and `shell…`; it never has `extrude`.
  • Feature actions are chips, like constraints. They live in the same selection popover under `FEATURE`, not in a footer and not on a raw click.
  • Form inputs follow PICKS.md. Faces/edges are always live, profiles switch to the sketch, an axis/support uses `pick`; each multi input is a row plus a remove list before the value.
  • Box/lasso select sketch geometry in ordinary select, respecting the filter. Backspace deletes the set. Profile mode is the only marquee that picks regions.
  • Geometry + dimensions may mix. Constraint chips use the geometry subset; the dimension row edits/deletes; the footer delete handles all.
  • A constraint is single. Clicking one replaces the set; it has name, participants, delete and reset position.
  • Model families do not mix yet. Edges and faces are separate; no direct feature on click.
  • Selection has one visual language. Lines/edges are a highlighter block under an ink centerline, faces/regions are a wash, points are a fill with an ink ring, and hover is the same block at lower opacity.
  • References are click-only. They can participate in constraints/dimensions, but delete skips them.

Open questions

  • Should there be a `regions` filter, or is profile mode enough for marquee region selection?
  • Should an empty model click clear the face/edge set and keep the form, like profiles, or cancel the form (MODES D8)?
  • Should a profile list row use area or boundary count as its detail?
  • Does a double-click on one dimension in a multi-selection make it the sole selection?
  • Should `new sketch` appear on a face popover as well as the insert gap?
  • Should the delete summary name skipped references?
  • Do model edges/faces need any Delete action, or is the feature step always the unit?
